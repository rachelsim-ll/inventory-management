Factory Inventory Management System

Complete System Architecture & Technical Documentation

System Overview

A modern full-stack web application for factory inventory and order management. The system provides real-time visibility into inventory levels, order status, demand forecasting, and spending analysis through an intuitive dashboard interface.

Built with Vue 3 on the frontend and Python FastAPI on the backend, the system uses in-memory data storage with JSON-based persistence for demonstration purposes.

Technology Stack

Frontend

Vue 3 with Composition API for reactive, maintainable UI components

Vite for fast development and optimized builds

Axios for HTTP client requests to backend API

Backend

Python FastAPI for high-performance REST API

Pydantic for data validation and serialization

CORS Middleware for cross-origin requests

Data

JSON Files for mock data storage

In-memory data structures for fast filtering and queries

No database (demo system) - data persists between server restarts

Component Layers

Presentation Layer (Frontend)

Vue 3 components and views handle UI rendering and user interactions. Reactive state management with refs and computed properties ensures responsive updates. Composables provide shared business logic across components.

API Layer (FastAPI Backend)

RESTful API endpoints provide data access and filtering. Pydantic models validate all requests and responses. CORS middleware enables cross-origin requests for development.

Data Layer (In-Memory Storage)

JSON files are loaded at server startup into Python dictionaries and lists. All filtering and queries operate on these in-memory structures for performance. No persistent database in this demo system.

Data Flow & Filtering Pipeline

Complete Request Lifecycle

1. User selects filters in Vue component
2. Frontend builds query parameters (warehouse, category, status, month)
3. Axios sends GET request to FastAPI endpoint
4. Backend receives request and extracts query parameters
5. apply_filters() applies warehouse, category, status filters
6. filter_by_month() applies temporal filters (month/quarter)
7. Pydantic model validates response data
8. JSON response sent back to frontend
9. Frontend updates refs with new data
10. Vue reactivity triggers component re-render

Vue 3 Composition API Patterns

Reactive State Management

Uses ref() for mutable state and computed() for derived data. Composables encapsulate shared logic like filters and authentication. This pattern keeps components clean and promotes code reuse.

Data Loading & Filtering

Components fetch data via centralized api.js module. Filters are applied through query parameters sent to the backend. Loading states are managed with refs to show spinners and error messages.

Filter System

The useFilters() composable provides reactive filter state shared across views. When filters change, components automatically reload data from the API through watchers.

Filtering Architecture

apply_filters() Function

Core filtering utility that handles warehouse, category, and status filters. Implements "all" value checking to skip filters when not specified. Uses list comprehensions for efficient in-memory filtering.

filter_by_month() Function

Handles temporal filtering for orders. Supports direct month matching (e.g., "2025-01") and quarter shorthand (e.g., "Q1-2025") through a QUARTER_MAP constant. Gracefully handles missing date fields.

Pydantic Data Models

Defines strict schemas for InventoryItem, Order, DemandForecast, BacklogItem, PurchaseOrder, and others. Provides automatic validation, serialization, and API documentation. Always returned as response_model for type safety.

Data Structure & Models

Core Entities

Inventory Items

SKU, name, category, warehouse location, quantity on hand, reorder point, unit cost, and last updated timestamp. Supports filtering by warehouse and category.

Orders

Order number, customer, line items, status (Processing/Backordered/Delivered), dates (order, expected delivery, actual delivery), total value, warehouse, and category. Filterable by all four dimensions.

Demand Forecasts

Item SKU, current demand, forecasted demand, trend direction, and period. Helps with inventory planning and procurement decisions.

Backlog Items

Order reference, item SKU, quantity needed vs available, days delayed, priority level, and associated purchase order status. Tracks unfulfilled orders requiring attention.

Purchase Orders

Supplier name, quantity ordered, unit cost, expected delivery date, status, and creation date. Links to backlog items for procurement tracking.

Time Period Filtering

Important: The system supports both monthly and quarterly filtering. Monthly format is YYYY-MM (e.g., "2025-01"), and quarters are Q#-YYYY (e.g., "Q1-2025"). Inventory endpoints don't support time filtering as inventory has no temporal dimension.

Key Architectural Patterns

Centralized API Client

All HTTP requests flow through client/src/api.js. Each method builds query parameters conditionally (checking for "all" values) and returns raw data. This centralizes error handling and makes testing easier.

Filter-Driven Data Flow

Filters originate in the UI, are passed to the API as query parameters, applied server-side, and results are cached in frontend refs. Components watch filter changes and reload data automatically through reactivity.

Pydantic Validation Gateway

All FastAPI endpoints specify response_model using Pydantic BaseModel subclasses. This enforces type safety, auto-generates API documentation, and prevents malformed data from reaching the frontend.

In-Memory Filtering

JSON data is loaded at server startup into Python data structures. Filtering happens entirely in-memory using list comprehensions. This approach is fast for demo data but would need optimization (database indexes, pagination) for production scale.

CORS for Development

FastAPI middleware allows all origins during development. This enables the Vite dev server (port 3000) to communicate with the API server (port 8001). In production, this should be restricted to specific origin(s).

Important Implementation Notes

Data Persistence: JSON files are loaded at server startup. Changes made via the API do not persist after server restart. This is intentional for the demo system but would require a real database for production.
v-for Keys: Always use unique item identifiers (SKU, ID) as Vue v-for keys, never array indexes. Using indexes breaks reactivity when lists are filtered or reordered.
Date Validation: Before calling JavaScript date methods (.getMonth(), .getTime()), validate the date string with new Date(dateString) and check !isNaN(date.getTime()).
Filter Parameter Matching: When adding new filters, ensure consistency between frontend parameter names, API query parameter names, and backend filtering logic. Use lowercase for string comparisons.
Pydantic Model Updates: Whenever JSON data structure changes, update the corresponding Pydantic model in main.py. New fields should be marked Optional until all data is migrated.
Revenue Goals: System tracks monthly targets of $800K (single month) and $9.6M YTD (all months). These values are used in dashboard calculations and spending analysis.

The current architecture is optimized for demonstration. To scale to production:
